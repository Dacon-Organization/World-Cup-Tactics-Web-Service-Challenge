## 이 서비스가 푸는 문제

축구를 보다 보면 누구나 한 번쯤 "내가 감독이라면 저렇게 안 하는데"라고 생각합니다.
그런데 그 생각을 **확인해 볼 방법이 없습니다.**

웹에는 이미 여러 라인업 빌더가 있지만, 조사한 범위에서 이들은 모두 **배치를 그리고 이미지로 내보내는 도구**입니다.
선수를 옮겼을 때 *그래서 결과가 어떻게 달라지는지*를 알려주지 않습니다.

이 서비스는 거기서 시작합니다. **배치를 바꾸면 예측이 바뀝니다.**

세 모드를 관통하는 축은 하나입니다 — **어떤 조작이든 즉시 예측치가 갱신된다.**

## 기술적 특징

**학습은 오프라인, 추론은 브라우저에서.**

머신러닝 모델은 Python으로 사전 학습한 뒤 ONNX로 내보내고, 실제 추론은 **브라우저 안에서 100% 로컬로** 수행합니다.

이 설계의 결과:
- **API 키가 필요 없습니다** — 누구나 링크만 열면 전체 기능을 확인할 수 있습니다
- **서버 호출이 없습니다** — 조작에 대한 반응이 즉각적입니다
- **오프라인에서도 동작합니다**

| 모델 | 역할 |
|---|---|
| xG 모델 | 슛 상황 → 득점 확률 |
| 경기 결과 예측 | 팀 강도 → 스코어라인 확률 분포 |
| 포메이션 상성 | 전술 파라미터 조합 → 기대 득점 차 |
| 선수 역할 적합도 | 선수 특성 → 포지션 적합 점수 |
| 몬테카를로 | 조별리그 반복 시뮬 → 진출 확률 |

## 기술 스택

- **프론트엔드**: Next.js 15 (App Router) · TypeScript (strict, `any` 금지) · Tailwind CSS v4 · shadcn/ui · Zustand
- **검증**: Zod (외부 경계 파싱) · Vitest (순수 함수 단위 테스트)
- **인터랙션**: Pointer Events 직접 구현 — 터치·마우스를 한 경로로 다루고,
  드래그 없이도 같은 결과를 내는 클릭·키보드 대안을 함께 제공하기 위함 (WCAG 2.5.7 AA)
- **서체**: Pretendard(SIL OFL 1.1) 서브셋 **자체 호스팅** — 폰트 CDN을 쓰지 않습니다
- **ML 추론**: ONNX Runtime Web (WASM, 자체 호스팅)
- **ML 학습**: Python · scikit-learn · LightGBM/XGBoost/CatBoost → ONNX export
- **배포**: Vercel

## 실행 방법

Node.js 20 이상이 필요합니다 (개발 환경 실측: Node 24.14 / npm 11.9).

```bash
npm install
npm run dev          # http://localhost:3000
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 프로덕션 빌드 |
| `npm test` | Vitest 단위 테스트 |
| `npm run typecheck` | TypeScript strict 검사 |
| `npm run gate` | **제출 게이트**(실명·참조 무결성·라이선스) — 실패하면 커밋하지 않습니다 |

`npm run gate`의 실명 검사(G1)는 **커밋되지 않는 로컬 대조 목록**
(`data/gate/real-names.txt`)을 읽습니다. 이 파일이 없으면 게이트는 통과가 아니라
**실패**합니다 — 조용히 통과시키면 아무것도 검사하지 않으면서 초록으로 보이기
때문입니다. 자세한 내용은 [docs/제출-게이트.md](docs/제출-게이트.md).

## 배포

### 🔗 <https://world-cup-tactics-web-service-chall.vercel.app>

가입·설치·API 키 없이 브라우저로 바로 열립니다. 모든 예측은 사용자 브라우저 안에서
계산되며, 모델 파일을 내려받은 뒤에는 외부 요청이 발생하지 않습니다.

**`main`에 머지하면 Vercel이 자동으로 배포합니다.** PR을 열면 프리뷰 배포가 따로 생겨
머지 전에 화면을 볼 수 있습니다.

| 파이프라인 | 트리거 | 하는 일 |
|---|---|---|
| Vercel GitHub 연동 | `main` 푸시 · PR | 프로덕션 배포 · PR 프리뷰 |
| [`ci`](.github/workflows/ci.yml) | PR · `main` 푸시 | 타입 → 린트 → 테스트 → G2·G3 게이트 → 빌드 |
| [`deploy`](.github/workflows/deploy.yml) | 수동만 | Vercel 연동이 끊겼을 때의 폴백 |

실명 게이트 G1은 대조 목록(실명)을 CI에 올리지 않기 위해 **로컬 전용**으로 둡니다.

배포 방식·프리뷰 보호 설정·문제 해결·배포 후 체크리스트는 [docs/배포.md](docs/배포.md)를 보세요.

## 주요 파일 구조

```
src/
├── app/          Next.js App Router — 페이지 셸은 전부 Server Component
├── components/   피치 · 전술 · 예측 · 리플레이 · 공유 컴포넌트
├── lib/          데이터 로드/검증 · 조정 계층 · 예측 엔진
├── store/        Zustand 슬라이스 (전술 / 예측 분리)
├── types/        데이터·Worker 계약 타입
└── data/         정적 JSON 4종 (formations · players · matches · defaults)
public/
├── fonts/        Pretendard 서브셋 woff2 + OFL 사본·파생 고지
├── model/        학습된 ONNX 모델 · 스코어 파라미터
└── ort/          ONNX Runtime Web wasm (자체 호스팅)
scripts/gates/    제출 게이트 (G1 실명 · G2 참조 무결성 · G3 라이선스)
notebooks/        ML 학습 파이프라인 (수집 → EDA → FE → 모델 → 평가 → 보고)
docs/             대회요강 · 기획 문서 · 리서치 원장
```
