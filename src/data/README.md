## 좌표 규칙

`x`는 0(좌)~1(우), `y`는 0(자기 진영)~1(상대 진영) 정규화 값입니다. 화면 크기와
무관한 배치를 보장하고, 화면 회전에도 같은 전술이 유지됩니다(F01-R6).

- `f433`은 [DESIGN.md §3.4](../../DESIGN.md)의 좌표를 **그대로** 씁니다 — 기획서 PDF에
  실린 그림과 같은 배치여야 하기 때문입니다.
- `f442`·`f343`·`f352`는 같은 좌표계 규칙(**좌우 대칭** · **라인 간 y 간격 0.20~0.26**)으로
  B2에서 신설했습니다 `[설계 결정]`.

## 가공명

`players.json`의 `displayName`은 **완전 가공명**입니다. 생성 스크립트·실명 대조 목록·
실명↔가공명 배정표는 모두 `data/`(gitignore 대상)에만 있고 **저장소에 들어오지
않습니다** — 규칙과 배정표가 커밋되면 그 자체가 연상 경로가 되기 때문입니다
(가공명_체계 §2-3 · ADR-005).

## 알려진 스키마 한계 — 교체 이벤트의 방향

데이터 설계 §2.3은 *"교체는 in/out 2행"*이라고만 정하고 **방향(IN/OUT) 필드를 두지
않았습니다.** 현재 `matches.json`은 그 규약대로 같은 분(minute)에 2행을 넣고,
**배열 순서를 OUT → IN으로** 씁니다(rsa 65': `kor-10` OUT → `kor-08` IN).

순서에 의미를 싣는 것은 깨지기 쉬우므로 v1.1에서 `direction: 'in' | 'out'` 필드를
추가하는 것이 맞습니다. 기획서 PDF가 동결이라 지금은 스키마를 바꾸지 않고
[vNEXT 변경노트](../../docs/planning/_changes/vNEXT-변경노트.md)에 적어 두었습니다.

## 이벤트에 없는 것

경고(카드)는 P13에서 확정됐지만 `MatchEvent.type`에 `card`가 정의되어 있지
않습니다(데이터 설계 §2.3). 타입에 없으면 행도 없습니다 — 미확정 이벤트를
화면에 띄우지 않는다는 F10-R3이 데이터 수준에서 보장되는 구조입니다.

멕시코전 후반 교체 1건은 출처 간 분(minute) 표기가 엇갈려 P13에서 `[부분 확인]`으로
남았으므로 **행을 넣지 않았습니다.**
