# 제출 게이트 — 실격·심사제외 차단 체계

> **1차 출처는 [대회요강.md](대회요강.md)입니다.** 이 문서는 요강의 실격·심사제외 조항을
> **검사 가능한 절차**로 번역한 것입니다. 요강과 이 문서가 충돌하면 요강이 우선입니다.
>
> **설계 원칙**: 실격 방어를 "조심하기"로 하지 않습니다. 조심은 마감 전날 밤에 실패합니다.
> 가능한 것은 **스크립트로 만들어 빌드를 막고**, 스크립트로 만들 수 없는 것은
> **날짜가 박힌 수동 절차**로 만듭니다.

## 1. 자동 게이트 — `npm run gate`

빌드 전 필수. **실패 시 종료 코드 1로 빌드를 중단합니다.** 우회 플래그를 만들지 않습니다.

```bash
npm run gate
```

### G1 `gate:names` — 실명·연상 표기 검사 (요강 3순위)

근거: [가공명_체계 §3](planning/data/version1.0/가공명_체계_v1_0.md) · P7 (서울서부지법 2010카합245)

| 검사 | 판정 |
|---|---|
| 실명 **완전 일치** | **실패** (0건이어야 함) |
| 초성 + 음절수 동시 일치 | **경고 → 수동 재검 필수.** 재검 기록 없으면 실패 |
| 로마자 표기 편집거리 ≤2 | **경고 → 수동 재검 필수** |

- **검사 대상**: `src/data/*.json` · `src/**/*.tsx|ts`(UI 문자열) · `public/**` · `docs/**`(공개 문서) · `notebooks/*.ipynb`(커밋본)
- **대조 목록**: 학습 파이프라인 내부의 실명 목록 + 최근 2개 대회 국가대표 소집 명단.
  **이 목록 자체는 커밋하지 않습니다** — 커밋하면 그 파일이 실명 노출이 됩니다.
  로컬 경로(`.gitignore` 대상)에서 읽고, 파일이 없으면 **게이트를 통과시키지 않고 실패**시킵니다
  `[설계 결정]`
- 제외 대상: 국가명(허용, P7) · 지명·경기장명(허용)

**B2 구현에서 확정한 두 가지** (`scripts/gates/names.ts`):

| 항목 | 결정 | 이유 |
|---|---|---|
| `docs/research/**` 완전일치 검사 | **제외하되 매 실행마다 적중 건수를 출력** | FIFA 공식 매치리포트 등 **1차 출처를 사실로 인용한 대조 기록**입니다. 퍼블리시티권이 문제 삼는 것은 서비스가 실명으로 얻는 이익이지 사실 확인 기록이 아니고, 지우면 "세 경기 팩트를 어떻게 확정했는가"의 감사 추적이 사라집니다. **제외를 조용히 하지 않는 것**이 조건입니다 — 최종 판단(수정·저장소 밖 이동·현행 유지)은 B8 M1에서 사람이 합니다 |
| 2음절 실명 중 일반어와 충돌하는 항목 | 완전일치 대조 목록에서 제외 | 실측 결과 일반 명사와 겹치는 이름 1건이 대회요강 원문을 포함한 전 문서에서 오탐을 냈습니다. 오탐이 많으면 게이트를 아무도 안 보게 되고, 그 상태가 곧 침묵 실패입니다 |

경고 재검 기록은 `scripts/gates/name-review.json`에 둡니다(가공명만 담으므로 커밋 가능).
기록되지 않은 경고가 남아 있으면 **실패**입니다.

> **"파일이 없으면 실패"가 왜 중요한가** — 대조 목록이 없을 때 조용히 통과시키면, CI나
> 다른 기계에서 게이트가 항상 초록으로 보이면서 실제로는 아무것도 검사하지 않습니다.
> 이런 침묵 실패가 실격의 전형적 경로입니다.

**B2 구현에서 확정한 예외 체계** (`scripts/gates/license-exceptions.json`):

허용 목록 밖 라이선스는 **패키지 이름·라이선스·`브라우저전달` 여부·사유가 기재되어야만**
통과합니다. 기재가 없으면 실패이고, `브라우저전달: true`면 기재가 있어도 실패입니다.

> **npm 의 production 의존성 여부를 합격 기준으로 쓰지 않는 이유** — Next.js 의 production
> 의존성에는 빌드 전용 도구(이미지 네이티브 바이너리, 브라우저 지원 데이터셋)가 섞여 있어
> "npm production = 브라우저 전달"이 성립하지 않습니다. 실제 번들 적재 여부는 **G4의 정적
> 분석**이 봅니다. G3은 인벤토리와 사유가 빠짐없이 존재하는지만 보증하고, production closure
> 소속 여부는 검토자가 보라고 화면에 표시만 합니다.

현재 예외 6건은 전부 빌드·개발 도구입니다: `lightningcss`(+플랫폼 바이너리)·`axe-core`
(MPL-2.0) · `argparse`(Python-2.0) · `caniuse-lite`(CC-BY-4.0) · `@img/sharp-win32-x64`
(Apache-2.0 AND LGPL-3.0-or-later).

**폰트는 이름을 바꿔 담았습니다** — OFL 1.1 §3과 공식 OFL FAQ 2.6이 *"웹폰트 서브셋은
수정본이며 예약 폰트 이름(RFN)을 쓸 수 없다"*고 정하므로, 서브셋 산출물의 패밀리명·파일명을
`RF Sans`로 변경했습니다. 아웃라인은 원본과 동일해 기획서 PDF와 글자 모양이 어긋나지
않습니다. 근거와 검증 방법은 [public/fonts/NOTICE.md](../public/fonts/NOTICE.md).

### G4 `gate:network` — 외부 요청 0건 (요강 5순위)

프로덕션 빌드 산출물을 정적 분석합니다.

- `.next/` 번들에서 `http://`·`https://` 리터럴 스캔 → **허용 목록(자기 도메인·OG 메타의
  canonical URL) 밖이면 실패**
- `ort.env.wasm.wasmPaths`가 `/ort/`(자체 호스팅)로 고정되어 있는지 확인 — **기본값이면 CDN을
  받으므로 실패**
- 폰트 `@font-face` src가 `/fonts/` 로컬인지 확인
- 환경변수 의존 코드(`process.env.NEXT_PUBLIC_*`)가 기능 동작에 필수인지 확인 → 필수면 실패
  (심사자는 키를 넣지 않는다)

**런타임 확인은 B8에서 별도로** — 실기기에서 네트워크 탭을 열어 모델 최초 로드 후 요청
0건을 눈으로 확인합니다. 정적 분석은 놓치는 경로가 있습니다.

## 2. 수동 게이트 — 스크립트로 만들 수 없는 것

### M1 비하·명예훼손 카피 검수 (요강 **2순위 — 심사 제외**)

**대상**: 사용자에게 보이는 **모든 문자열**. 코드 주석·문서는 제외(노출 표면 아님)이나
`docs/`는 공개되므로 포함합니다.

절차:

1. UI 문자열 전수 인벤토리 추출 (`src/**` 한글 리터럴 + `src/data/*.json` 표시 문자열)
2. 각 문장을 아래 기준으로 판정

| 금지 | 대체 |
|---|---|
| 특정 인물의 판단을 "잘못"으로 규정 | "다른 선택지도 있었다" |
| 특정 팀·국가의 능력 비하 | 사실 수치만 (스코어·xG는 출처 라벨과 함께) |
| 결과에 대한 평가·조롱 | 사실 서술 ("67' 득점 — {가공명}") |
| 단정형 예측 | 확률 + 신뢰구간 병기 |

3. **고위험 표면 3곳을 반드시 개별 검수**
   - S2a 경기 카드 진입 카피 ("이 경기, 당신이라면?" 계열)
   - S2b 개입 후 비교 패널 — 실제 결과와 시나리오를 나란히 두는 곳
   - 공유 카드 제목 ("같은 체코전, 다른 전술" 계열) — **외부로 유통되므로 최고 위험**

4. 검수 결과를 PR 본문에 기록 (심사 대비 감사 추적)

> **공유 카드가 최고 위험인 이유** — 카톡 미리보기로 문맥 없이 단독 유통됩니다. 본문에서는
> 중립적인 문장이 카드 제목으로 잘려 나가면 다르게 읽힐 수 있습니다.

**이 표를 두는 이유** — 심사자·리뷰어가 "가입 없이 되나?"를 물을 때, "확인했습니다"가 아니라
"그 코드가 존재하지 않습니다"로 답할 수 있어야 합니다. 그것이 더 강한 보증입니다.
