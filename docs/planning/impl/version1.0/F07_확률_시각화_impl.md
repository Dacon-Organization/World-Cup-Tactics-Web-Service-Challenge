## 2. 컴포넌트 트리

```
src/components/prediction/
├── PredictionPanel.tsx     (Client) — F05 §2에서 만든 조립 지점
├── ProbabilityBar.tsx      (훅 없음) — **B4 파일 수정**: 라벨 산출을 allocate100으로 교체
├── DotGrid10x10.tsx        (훅 없음) — 순수 SVG 100칸
├── WilsonBandRow.tsx       (훅 없음) — 범주별 "승 49% · 95% 구간 47–51%"
└── HopsPlayer.tsx          (Client) — 유일하게 타이머를 드는 컴포넌트
src/lib/prediction/allocate.ts  — 최대잔여법 100칸 배분 (순수)
```

```typescript
interface DotGridProps {
  /** 합이 정확히 100인 정수 3개 */
  counts: OutcomeCounts;
}
interface WilsonBandRowProps {
  counts: OutcomeCounts;
  band: Band | null;      // null이면 밴드 행을 숨긴다(사전 계산값 상태)
  iterations: number | null;
  degraded: boolean;
}
interface HopsPlayerProps {
  frames: Frame[];
}
```

**`HopsPlayer`만 Client인 이유** — 나머지 셋은 훅이 없어 Server/Client 어느 쪽에서 렌더해도
같은 HTML이 나옵니다. B4의 `ProbabilityBar`가 세운 성질을 유지하는 것이며, 그래야 JS가 죽어도
확률 시각화가 화면에 남습니다(F08-R5).

**시각화 라이브러리를 쓰지 않습니다** (F07 §4 `[설계 결정]`) — 100개 `<rect>`와 3개 텍스트 행에
차트 라이브러리를 들이면 번들 예산만 쓰고 얻는 것이 없습니다.

## 3. 상태

| 값 | 위치 | 이유 |
|---|---|---|
| `p` · `band` · `frames` · `iterations` · `degraded` | `predictionStore` (F05 §3) | 엔진 산출물 |
| `counts` (100칸 배분) | **어디에도 없음** — 매 렌더 `allocate100(p)` | 파생값을 스토어에 넣지 않는다 (구현규약 §3) |
| `playing` · `index` | `HopsPlayer` 로컬 | 표시 전용. 다른 컴포넌트가 읽지 않는다 |

F07 §8은 `visualization{mode, hopsPlaying, frames[]}`를 상태로 적었지만, `frames`는 이미
`predictionStore`에 있고 `hopsPlaying`은 한 컴포넌트 안에서만 쓰입니다. **스토어 슬라이스를
새로 만들지 않습니다** — 두 곳에 같은 값이 생기는 것을 막는 것이 구현규약 §3의 취지입니다.

## 4. 알고리즘·수식

### 4.1 100칸 배분 — 상호 불일치 0을 만드는 유일한 장치

```typescript
export function allocate100(p: Probabilities): OutcomeCounts;  // 합 = 정확히 100
```

최대잔여법(largest remainder):

```
raw_k   = p_k · 100
base_k  = floor(raw_k)
남은 칸 = 100 − Σ base_k          (0~2칸)
소수부 raw_k − base_k 가 큰 순서로 1칸씩 배분
동률이면 승 → 무 → 패 고정 순서    // 결정론 확보
```

**퍼센트 숫자도 이 결과를 씁니다.** `Math.round(p·100)`을 따로 쓰면 합이 100이 아니게 됩니다 —
양방향 모두 실측으로 확인했습니다.

| `p` | `Math.round` | 합 | `allocate100` |
|---|---|---|---|
| `(0.495, 0.305, 0.200)` | `50, 31, 20` | **101** | `50, 30, 20` |
| `(0.157905, 0.245129, 0.596966)` | `16, 25, 60` | **101** | `16, 24, 60` |
| `(0.894807, 0.064186, 0.041007)` | `89, 6, 4` | **99** | `90, 6, 4` |

**배열은 100칸인데 퍼센트 합이 101**인 화면은 그대로 심사 감점 소재입니다. F07 수용 기준
"상호 불일치 0"은 세 표현이 같은 정수 3개를 공유할 때만 구조적으로 성립합니다.
(무작위 확률 30만 건에서 `allocate100`의 합계 100 불변식 위반 0건을 확인했습니다.)

**B4의 `ProbabilityBar`를 수정합니다** — 현재 라벨이 `Math.round(shares[k] · 100)`로 독립 계산
중입니다. 막대 **폭**은 연속값(`shares`)을 그대로 쓰되(1%p 미만 차이가 폭에서 사라지면 안 됨),
**라벨 숫자는 `allocate100`** 로 바꿉니다. 폭과 라벨의 근거가 다른 것은 의도이며, 사용자가 읽는
숫자는 언제나 하나입니다.

### 4.2 10×10 배열 — `DotGrid10x10`

- 채움 순서: **행 우선, 위에서 아래로**(top/row). 승 → 무 → 패를 이어서 채웁니다.
- P12가 배제한 것: 중앙 시작(central)·무작위 배치(random). 둘 다 개수 지각을 왜곡합니다.
- 순수 SVG `viewBox="0 0 10 10"` + `<rect>` 100개. 반응형은 `width: 100%`와 `aspect-ratio: 1`.
- 색은 기존 시맨틱 토큰 `--color-win` · `--color-draw` · `--color-lose`.

```
접근성: <svg role="img" aria-label="승리 49칸, 무승부 30칸, 패배 21칸. 100번 중 49번 승리">
        개별 칸에는 aria-hidden — 100개가 각각 읽히면 패널을 벗어날 수 없다
```

**색 충돌 메모** — 결과 3색과 포지션 4색이 현재 같은 값이고 형태로만 구분됩니다. 이 배열은
형태 구분이 없는(전부 같은 사각형) 유일한 화면이라 색 충돌이 가장 크게 드러나는 지점입니다.
**이 블록에서는 토큰을 바꾸지 않습니다** — 팔레트는 동결된 기획서 PDF에서 역추출한 값이고,
변경은 다음 디자인 재설계 블록의 소관입니다. 여기서는 각 구간에 텍스트 라벨을 반드시 붙여
색 단독 전달이 되지 않게 하는 것으로 방어합니다.

### 4.3 Wilson 밴드 표시 — `WilsonBandRow`

밴드 값은 F06이 계산해 옵니다. 이 문서는 **놓는 방법**만 정합니다.

**정본은 텍스트 3행입니다** `[설계 결정]`

```
승  49%   95% 구간 47–51%
무  30%   95% 구간 28–32%
패  21%   95% 구간 19–23%
5,000회 시뮬레이션
```

3분할 막대 위에 신뢰구간 3개를 겹쳐 그리면 360px 화면에서 서로 침범합니다. 텍스트는 좁은
화면에서도 정확하고, 스크린리더에서 그대로 읽히며, F07-R3(숫자 병기)을 자동으로 만족합니다.

**보조로 막대 경계에 whisker를 얹습니다** — 승/무 경계는 누적 `p_win` 지점이고 그 지점의
불확실성이 곧 승리 밴드이므로, 경계에 짧은 가로 눈금을 그리는 것은 기하학적으로 정확합니다.
장식이 아니라 같은 수의 다른 표현입니다.

**`band === null` 이면 밴드 행 전체를 숨깁니다** — 첫 페인트(사전 계산값)와 `infer` 직후에는
MC가 아직 안 돌았으므로 밴드가 없습니다. 이때 `0–100%` 같은 자리표시자를 넣으면 없는 정보를
있는 것처럼 보이게 합니다. 반복 횟수 표기도 같이 숨깁니다.

**강등 표기**(F06-R7)는 반복 횟수 줄에 붙입니다 — `"2,500회 시뮬레이션 · 기기 성능에 맞춰 낮췄습니다"`.

### 4.4 HOPs 재생 — `HopsPlayer`

- 한 번에 **한 프레임**을 보여 줍니다: `"이번 시뮬레이션 · 2-1 승"`.
- 400ms/프레임, 20프레임 순환(= 8초 1바퀴). P12의 "<100ms 금지"는 400ms에서 자동 충족.
- 재생/정지 토글 1개. 정지 시 현재 프레임을 그대로 둡니다(0으로 되감지 않음).

```typescript
useEffect(() => {
  if (!playing || frames.length === 0) return;
  const id = setInterval(() => setIndex((i) => (i + 1) % frames.length), HOPS_FRAME_MS);
  return () => clearInterval(id);
}, [playing, frames]);
```

**배열과 역할이 다릅니다** (F07 §4) — 배열은 *집계*를, HOPs는 *개별 시뮬레이션 한 번*을 보입니다.
"62%"가 추상적으로 느껴지는 사용자에게 "2-1 승, 0-0 무, 1-3 패…"가 지나가는 것이 확률의 의미를
전달하는 방식입니다. 그래서 둘 다 있어야 하고, 한쪽이 다른 쪽을 대체하지 않습니다.

`aria-live="off"` — 400ms마다 스크린리더가 읽으면 패널을 쓸 수 없게 됩니다. 대신 재생 영역에
정적 설명을 둡니다: `"개별 시뮬레이션 결과를 한 번에 하나씩 보여 줍니다. 확률 요약은 위 표에 있습니다."`

### 4.5 `prefers-reduced-motion` (F07-R6) `[설계 결정 — 계약 초과]`

```typescript
const reduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
```

계약 문구는 "자동 재생을 비활성화하고 **정적 배열만** 표시한다"입니다. 그대로 읽으면 HOPs를
통째로 없애는 것이 되는데, 그러면 이 사용자군은 개별 시뮬레이션을 볼 방법이 사라집니다.

구현은 이렇게 합니다: **자동 재생 경로를 완전히 제거하고**(타이머를 만들지 않음), 재생 토글
자리에 `"다음 시뮬레이션 보기"` 수동 버튼을 둡니다. 애니메이션 없이 같은 정보에 도달할 수
있습니다. 접근성 설정에 대한 응답은 **기능 박탈이 아니라 대안 제공**이라는 판단이며,
계약보다 넓은 구현이므로 §7에서 회수합니다.

`matchMedia`는 구독합니다 — 사용자가 OS 설정을 바꾸면 재생 중이던 타이머가 즉시 멈춰야 합니다.

### 4.6 갱신 동기화 (F07-R1·R5)

세 표현이 전부 `p` 하나에서 파생되므로 **갱신 시점이 갈릴 여지가 없습니다.** 별도 동기화 코드는
없고, 없는 것이 설계입니다.

`frames`는 배열 참조가 통째로 교체되므로 `useEffect([frames])`가 R5의 트리거입니다:
`playing = false`, `index = 0`. 새 프레임 세트로 **정지 상태에서 시작**합니다 — 재생 중이었다고
자동 재개하면, 전술을 바꾼 직후 화면이 스스로 움직이기 시작해 조작 결과를 읽기 어려워집니다.

## 5. 실패 경로

| 계약 | 코드 분기 |
|---|---|
| **F07-R4** 0%·100% 근접 | 밴드는 Wilson이라 수학적으로 [0,1] 내부(평가_설계 §4.4). 표시 직전 클램프는 부동소수점 방어. `allocate100`은 `p_k = 0`이면 0칸을 배분하며, 100칸 중 하나도 못 받은 범주가 있어도 **밴드 행과 퍼센트는 그대로 표시**한다 — "0%"와 "정보 없음"은 다르다 |
| **F07-R5** 재생 중 새 결과 | `useEffect([frames])` → 정지·0번 프레임. 구식 결과는 F05 §5의 세대 판정에서 이미 걸러졌으므로 여기 도달하는 `frames`는 항상 최신 |
| **F07-R6** reduced-motion | §4.5. 타이머 생성 경로 자체가 없어진다 — 조건부 `return` 하나가 아니라 `playing`을 켤 수 없게 한다 |
| `p === null` | B4의 `ProbabilityBar` 분기 유지("확률은 곧 표시됩니다"). 배열·밴드·HOPs는 렌더하지 않는다. **빈 패널을 만들지 않는다** |
| `band === null` | 밴드 행과 반복 횟수 줄을 숨긴다 (§4.3). 배열·퍼센트는 정상 표시 |
| `frames` 비어 있음 | `HopsPlayer` 자체를 렌더하지 않는다. 토글도 없앤다 — 눌러도 아무 일이 없는 컨트롤을 두지 않는다 |
| `allocate100` 입력 합이 1이 아님 | 구현규약 §4 계약 위반. `p`를 합으로 정규화한 뒤 배분하고 `console.error`. 화면은 100칸을 유지 |
| 언마운트 중 타이머 잔존 | `useEffect` 정리 함수에서 `clearInterval`. 정리 없이 두면 패널을 접었다 폈을 때 타이머가 중첩돼 400ms가 200ms가 된다 |

## 6. 테스트

| 층 | 대상 |
|---|---|
| 단위 (Vitest) | `allocate100` — 합이 **항상 정확히 100**(무작위 확률 10,000건), 각 원소 ≥0 |
| 단위 | `allocate100` 동률 처리 — `p = (1/3, 1/3, 1/3)` → `(34, 33, 33)` 결정론 |
| 단위 | `allocate100` 경계 — `p = (1, 0, 0)` → `(100, 0, 0)`, `p = (0.999, 0.0005, 0.0005)` → 합 100 |
| 단위 | 불일치 0 — 임의 `p`에서 `DotGrid`의 칸 수 합계와 `ProbabilityBar` 라벨 합계가 동일 |
| 상호작용 | `HopsPlayer` — 가짜 타이머로 400ms마다 index 증가, 정지 토글 시 증가 중단, `frames` 교체 시 정지·0번 |
| 상호작용 | reduced-motion 모의(`matchMedia` 스텁) → 타이머 미생성, 수동 버튼 노출 |
| 접근성 (수동) | 스크린리더에서 배열이 한 문장으로 읽히는가 · HOPs 재생이 낭독을 방해하지 않는가 |
| 실기기 (B8) | 360px 폭에서 밴드 3행이 줄바꿈 없이 읽히는가 · 배열 칸이 구분되는가 |
