# 배포

> **왜 미리 세우는가.** 요강은 "배포 URL이 8/3~8/18 상시 접근 가능"할 것을 요구하고,
> 접근 불가는 **결격**입니다([제출-게이트](제출-게이트.md)). 마감 직전에 배포를 처음
> 시도하는 것이 이 프로젝트에서 가장 값싼 실격 경로입니다. 그래서 기능이 다 끝나기 전에
> 배포부터 세우고, 그 뒤로는 머지할 때마다 자동으로 최신 화면이 올라갑니다.

| 항목 | 값 |
|---|---|
| **배포 URL** | <https://world-cup-tactics-web-service-chall.vercel.app> |
| 배포 방식 | **Vercel GitHub 연동** — `main` 푸시를 Vercel이 직접 받아 프로덕션 배포 |
| 리전 | `icn1` (서울) |
| 검증 파이프라인 | GitHub Actions [`ci.yml`](../.github/workflows/ci.yml) — PR·`main` 푸시 |
| 폴백 | [`deploy.yml`](../.github/workflows/deploy.yml) — 수동 실행 전용 (§4) |

---

## 1. 정본 경로 — Vercel GitHub 연동

Vercel의 GitHub App이 이 저장소에 설치돼 있습니다. `main`에 머지되면 **Vercel이 직접**
빌드해서 프로덕션 도메인을 새 배포로 전환합니다.

- GitHub Actions도, `VERCEL_TOKEN`도, Secrets도 **필요 없습니다.**
- 배포 상태는 저장소 우측 **Deployments**와 커밋 옆 `vercel[bot]` 체크로 보입니다.
- PR을 열면 **프리뷰 배포**가 따로 생깁니다 — 머지 전에 화면을 볼 수 있습니다.

> **프리뷰는 로그인이 필요합니다.** Vercel의 Deployment Protection이 기본으로 켜져 있어
> 배포별 URL(`...-<해시>.vercel.app`)은 Vercel SSO로 302 됩니다. **프로덕션 도메인은
> 보호 대상이 아니라 누구나 열 수 있습니다**(실측 200). 요강 "심사자가 별도 키 없이 확인"은
> 프로덕션 도메인 기준이므로 충족입니다.
>
> 로그아웃 상태의 휴대폰으로 **프리뷰**까지 확인하고 싶다면 Vercel 프로젝트
> Settings → Deployment Protection에서 Vercel Authentication을 끄면 됩니다.
> **프로덕션 도메인 공개 여부와는 별개 설정입니다.**

## 2. 검증 파이프라인 — `ci.yml`

`pull_request` + `push: main`. 브랜치별 `concurrency`로 연속 푸시 시 이전 실행을 취소합니다.

| 단계 | 명령 | 막는 것 |
|---|---|---|
| 타입 | `npm run typecheck` | strict 위반·`any` 누수 |
| 린트 | `npm run lint` | ESLint·a11y 규칙 위반 |
| 테스트 | `npm test` | 조정 계층·스토어 회귀 |
| G2 | `npm run gate:refs` | 데이터 스키마·참조 무결성 깨짐 |
| G3 | `npm run gate:license` | 허용목록 밖 라이선스 유입 |
| 빌드 | `npm run build` | 프로덕션 빌드 실패 |

**주의: CI와 Vercel 배포는 서로를 막지 않습니다.** Vercel은 자기 빌드가 성공하면 배포하고,
CI 실패를 기다리지 않습니다. 게이트가 배포를 차단하는 유일한 지점은 **PR 머지**입니다 —
즉 `main`에 직접 푸시하지 않는 한 게이트를 통과한 코드만 배포됩니다.

## 3. CI가 검사하지 않는 것 — G1(실명 게이트)

| 게이트 | CI | 이유 |
|---|:---:|---|
| G1 `gate:names` | ❌ | 대조 목록 `data/gate/real-names.txt`가 **실명을 담아 커밋 금지**. `/data/`는 `.gitignore` 대상이고, 게이트는 목록이 없으면 통과가 아니라 **실패**하도록 설계돼 있습니다([`scripts/gates/names.ts`](../scripts/gates/names.ts)) |
| G2 `gate:refs` | ✅ | 입력이 전부 커밋된 파일 |
| G3 `gate:license` | ✅ | 입력이 `node_modules` + 커밋된 예외 목록 |

실명 목록을 GitHub Secrets에 넣으면 CI에서 G1을 돌릴 수는 있습니다. 하지만 그것은 **실명
유출 경로를 하나 더 만드는 일**이고, 게이트가 막으려던 위험(P7 실명 경계)을 게이트 운영이
스스로 늘리는 셈이라 하지 않습니다.

→ **G1은 로컬 전용 수동 게이트**입니다. 실제 통과 시점은 B9 최종 커밋 직전의 로컬
`npm run gate` 전량 실행입니다.

```bash
npm run gate
```

### 플랫폼별 네이티브 바이너리 (G3 관련)

개발은 Windows, CI 빌드는 Linux라 sharp·lightningcss의 네이티브 패키지 **이름이 다릅니다**.
`scripts/gates/license-exceptions.json`에 양쪽을 모두 기재해 두었습니다. 지금 플랫폼에 없는
쪽은 게이트가 `다른 플랫폼용 기재 (이 환경에는 미설치)` 참고 줄로만 표시합니다 — **지우면
반대 플랫폼에서 게이트가 깨집니다.**

## 4. 폴백 — `deploy.yml` 수동 실행

Vercel 연동이 끊기거나 Vercel 쪽 빌드가 막혔을 때 **GitHub Actions 러너에서 빌드해
업로드**하는 경로입니다. 평소에는 트리거되지 않습니다(`workflow_dispatch` 전용).

쓰려면 Secrets 3종이 필요합니다. **Settings → Secrets and variables → Actions**:

| 이름 | 얻는 곳 |
|---|---|
| `VERCEL_TOKEN` | <https://vercel.com/account/tokens> → Create Token |
| `VERCEL_ORG_ID` | 레포 루트에서 `npx vercel link` 후 `.vercel/project.json`의 `orgId` |
| `VERCEL_PROJECT_ID` | 같은 파일의 `projectId` |

`.vercel/`은 이미 `.gitignore` 대상이라 커밋되지 않습니다. 셋 중 하나라도 없으면 워크플로는
**첫 단계에서 사람이 읽을 수 있는 오류로 실패**합니다 — 조용히 건너뛰고 초록불을 보여 주지
않습니다.

## 5. 문제 해결

| 증상 | 원인 · 대처 |
|---|---|
| 머지했는데 화면이 그대로 | Vercel 빌드 진행 중(1~2분)이거나 실패. 저장소 **Deployments** 탭에서 상태 확인 |
| 배포별 URL이 로그인 화면으로 감 | 정상 — Deployment Protection. 프로덕션 도메인을 쓰거나 §1의 설정을 끄기 |
| 프로덕션 도메인이 404/로그인 | **결격 위험.** Vercel 프로젝트 Settings → Domains에서 프로덕션 도메인 연결과 보호 설정 확인 |
| CI만 빨간불인데 배포는 됨 | 정상 동작(§2). 배포를 되돌리려면 Vercel Deployments에서 이전 배포를 Promote |
| G3만 CI에서 실패 | 새 의존성의 Linux 네이티브 변종이 예외 목록에 없음 → 실패 로그의 패키지 이름을 예외 목록에 추가 (§3) |
| 배포는 성공인데 화면이 옛날 것 | 브라우저 캐시 또는 Service Worker(F05에서 도입 예정). 시크릿 창으로 재확인 |

## 6. 확인 체크리스트 (배포 후)

- [ ] 프로덕션 도메인이 200으로 열린다
- [ ] **시크릿 창**에서 로그인·가입 없이 열린다 (요강: 별도 키 없이 확인 가능)
- [ ] **모바일 회선**(Wi-Fi 끄고 LTE)에서 열린다 — 심사자가 모바일로 열 가능성이 전제
- [ ] 첫 페인트에 피치·토큰·확률이 이미 있다 (F08-R1 · SSR 기본 상태)
- [ ] 개발자도구 네트워크 탭에 **외부 도메인 요청 0건** (C1 온디바이스 주장)
