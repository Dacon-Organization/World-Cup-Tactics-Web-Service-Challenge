  • DONE
    데스크톱 가로 피치 — 오른쪽 쏠림의 원인은 "좁은 폭"이 아니라 세로 피치였다
    실측: 오른쪽 열이 320px 폭에 1360px(뷰포트 높이의 1.9배)을 쌓는데 왼쪽 640px에는 269px 피치만. 원인은 max-width: calc(56dvh * 2/3) — 세로 피치의 폭이 가용 높이에 묶여 가로를 더 줘도 커지지 않았다. 눕히니 같은 높이 예산(48dvh)에서 폭이 1.93배. 컨트롤은 하단 2열 바(좌 전술 · 우 예측)로 내려 D-1의 "조작 중 확률이 보인다"를 세로에서 가로로 옮겼다
  • DONE
    방향 전환을 전부 CSS로 — 서버가 뷰포트를 몰라도 된다
    정규화 좌표(x 좌→우 · y 자기진영→상대진영)는 불변. 토큰은 --nx/--ny 사용자 정의 속성 + calc(), SVG는 viewBox를 세로형으로 둔 채 상자를 눕혀 rotate(90deg). 방향을 React 상태로 들면 데스크톱 첫 페인트가 세로로 나왔다가 튀고 JS가 죽으면 영영 세로다(F08-R5 퇴행). 부수 효과: pitchDistance·nearestSlot·resolveDrop·조정 계층·예측 엔진 한 줄도 안 바뀜. JS가 방향을 아는 곳은 포인터 역변환·방향키 축·카드 개폐 방향 세 군데뿐
  • DONE
    선수 정보 카드 — 모달이면 조작이 죽는다
    토큰 안이 약어로 차면서 가공명이 화면에서 사라지므로 선택·호버 팝오버를 신설(가공명 + 포지션 한글명 + 프로파일 4종). 모달로 만들 수 없는 이유: 토큰 탭은 F03 클릭-클릭 이동의 "선수 선택"이고 다음 탭이 "목적지"라, 포커스 트랩·배경 차단이 들어가면 이동 경로가 통째로 죽는다. pointer-events: none으로 카드 위 탭이 그대로 피치에 닿게 했다. 여는 방향은 프레임 백분율로 계산해 항상 안쪽으로 — 임계값 35/65는 가장 좁은 프레임(249px)에서 카드 176px가 잘리지 않는 값. 호버는 420ms 지연 + @media (hover: hover)로 터치 기기 제외
  • DONE
