🔎 발견 (구현·검증이 아니었으면 놓쳤을 것)

  • 계약 결함
    WorkerResponse에 세대 식별자가 없다
    요청(TacticContext)에는 B4가 generation을 넣어 뒀는데 응답에 없다. cancel이 청크 경계에서만 반영되는 구조와 겹치면 취소 직후 도착한 옛 결과를 새 결과로 오인하는 경로가 실재(F04-R4 위반). 유니온 갈래는 그대로 두고 교차 타입 봉투로 얹음 → 단위 테스트로 고정
  • 계약 결함
    iterations: 5000 | 25000이 F06-R7 강등을 표현하지 못한다
    "반복을 절반으로"가 계약인데 타입이 그 상태를 담지 못함. number로 넓히지 않고 절반값 2개만 유니온에 추가 — 화면에 표기되는 "N회"가 근거 있는 값만 되도록
  • 함정
    wasmPaths를 문자열 접두사로 주면 조용히 404가 난다
    1.27.0 번들 코드를 직접 디코딩: 내장 glue 사용 조건이 임베드 && !(mjs재정의 || 접두사). 접두사를 주는 순간 .mjs까지 같은 경로에서 받으려 하고, 우리는 그것을 호스팅하지 않는다. 객체형 { wasm }이어야 요청이 .wasm 1건으로 끝남. numThreads=1도 같은 분기
  • 문서 오류
    1.27.0에는 비스레드 전용 wasm 바이너리가 없다
    ML 설계 §5.4의 "non-threaded 선택"은 파일명 기준 서술이 낡은 것. 의도(스레드 풀 없음·COOP/COEP 불필요)는 numThreads=1로 보존 → B8 v1.1 회수
  • 검증이 잡음
    정수 반올림이 F06 수용 기준을 관측 불가능하게 만들었다
    밴드를 정수로 찍으니 5,000회와 25,000회의 승리 구간이 둘 다 48–50%. 밴드 끝점은 p·N의 결정론적 함수라 소수 1자리가 과장이 아님 → 1자리로 정정(점추정은 배열과 정수 공유 유지). 처음 판단이 틀렸던 부분
  • 설계 변경
    infer를 런타임 경로에서 뺐다
    계약의 result payload가 하나뿐이라 infer가 응답하려면 MC를 안 돌린 신뢰구간을 만들어야 한다 — 거짓 정보. MC가 수 밀리초라 2단으로 나눌 실익도 없어 ready 직후 바로 simulate. Worker는 infer를 빠른 모드와 같게 처리(계약 메시지를 조용히 무시하지 않음)
  • 확인됨
    webpack이 type: 'module'을 벗겨 고전 워커로 번들한다
    미검증으로 남겨 뒀던 항목. new Worker(url, { type: void 0 }) + importScripts로 ORT 청크 로드 — 모듈 워커 미지원 브라우저까지 커버되므로 결과적으로 더 넓다
